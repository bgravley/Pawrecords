# Pet Travel Requirements — Seed Cohort Plan

Status: review only. This is not a publication list and does not authorize any page to go live.

## Selection method

The first destination cohort should balance:
1. routes already researched by the existing YourPetPass travel engine
2. observed Trip Planner demand (directional only; current volume is too small for strong conclusions)
3. regulatory complexity / owner utility
4. cluster value and geographic breadth
5. ability to source current rules from responsible official authorities

## EU architecture note

France/Germany/Italy/Spain/Portugal/Netherlands should share normalized EU-level rules where the EU rule is genuinely common, with country-level overrides only for national differences. Do not duplicate the same EU legal rule into independent prose records that can drift.

## U.S. architecture note

Separate:
- U.S. federal entry rules
- state/territory destination rules where material
- airline carriage policy

Puerto Rico and other territories should not be treated as foreign countries merely because the user flies there.

## Review packet for each destination

Before a destination guide can leave draft:
- responsible entry authority
- origin/export authority when needed
- species scope
- microchip
- rabies
- antibody titer
- health certificate
- government endorsement
- parasite/treatment rules
- import permit
- quarantine
- arrival inspection/customs
- transit caveats
- timing windows
- exceptions
- source reviewed date
- route/origin categories that materially change the answer
- proposed direct-answer block
- proposed decision/timeline module
- cannibalization check against existing Pet Guides

## Page-generation rule

A researched destination does not automatically equal a page.

Default: one destination authority page with interactive origin/species context.

Create a route-specific indexable page only when:
- the legal path materially differs,
- users have a distinct practical question,
- the answer cannot be handled cleanly as a conditional module on the destination page, and
- the page has sufficient primary-source support and unique value.

## User-triggered missing destination

When a user requests an uncovered route:
1. satisfy the user's Trip Planner request using the existing research engine;
2. normalize reusable official-source findings;
3. increment aggregate demand;
4. create/update a noindex publication candidate;
5. compare against existing destination/route intent;
6. queue for source/editorial review.

No raw AI result should auto-publish.
