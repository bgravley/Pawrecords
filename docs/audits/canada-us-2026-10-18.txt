Implementation and limits
Server inserts seven reviewed conditional baseline tasks after AI verification.
AI may add only carrier/airport logistics, with typed HTTPS sources. Overlap
with protected legal topics fails the request before cache write or successful
usage accounting. Warning labels do not override this check. This intentionally
favors correctness over availability: even a correct overlapping AI supplement
can be rejected. No regex can verify all possible paraphrases or source content;
this is a bounded guardrail plus deterministic baseline, not universal legal verification.
Unknown/high-risk history is explicitly referred to authorities; Canada departure
alone never grants low-risk eligibility. State-specific clearance is not inferred.
Six calendar months is not converted to an invented 180/182-day deadline.

Both normal requests and cron/admin prewarming use the same server path.
Version prefix preserves the existing departure-date/arrangement key. Old rows
are unreachable after deployment, and new cache hits must contain the unchanged
baseline and valid supplements. Other routes and auth/tier/quota controls retain
existing behavior. No database schema change or production mutation performed.
Previously saved trip checklists are not rewritten by this patch.
